# AI 漫剧自动化生产管线

**把「剧本 → 分镜 → 出图 → 出视频 → 配音 → 配乐 → 剪辑 → 素材包交付」
做成一条可插拔、可回溯、可审计的自动化生产管线。**

> 27,996 行 Python ｜ 9 类 AI 能力 47 个实现 ｜ 122 个 REST 端点 ｜ 18 个管理页面 ｜ 81 个测试脚本

---

## 这个项目解决什么问题

AI 短剧/漫剧的生产链路涉及大模型写稿、文生图、图生视频、TTS、BGM、视频合成
等多个异构环节。实际做起来会遇到四类硬问题：

| 问题 | 具体表现 |
|---|---|
| **任意一环换供应商都要改代码** | 从 A 家图模型换到 B 家，业务逻辑跟着重写 |
| **生成结果不可复现** | 同一 seed 出两次图不一样；角色跨镜换脸换衣 |
| **成本波动大** | 40 镜跑完才知道花了多少，中途失控无感知 |
| **误操作难以恢复** | 一次批量操作失误，一整集产出没了 |

这个项目的目标：**做一个「换模型不改管线、每一步都可回滚、每一分钱都可核算」的生产底座。**

## 核心设计

### 三层架构

```
┌──────────────────────────────────────────┐
│  服务层  122 个 REST 端点 + 18 个管理页面  │
├──────────────────────────────────────────┤
│  核心层  编排 · 状态机 · 成本 · 版本 · 一致性│
├──────────────────────────────────────────┤
│  插件层  9 类能力 · 47 个实现 · 统一签名     │
└──────────────────────────────────────────┘
```

**插件层**抽象了 9 类能力（剧本/图像/视频/语音/音乐/剪辑/日志/3D场景/电台），
47 个实现全部遵循同一输入输出签名。**换供应商只注册一个新文件，0 行业务改动。**

### 关键机制

| 机制 | 解决什么 |
|---|---|
| **跨进程状态同步** | 文件锁（msvcrt/fcntl 双实现）+ mtime 检测 + 原子替换，把 78% 的写入丢失降到 0% |
| **LLM 输出三级回落** | 直接解析 → 截取 JSON → 括号栈修复，避免截断导致 40 镜白跑 |
| **角色定妆照** | 首跑为每个角色生成定妆照并缓存，每镜自动带参考图（支持多角色多图） |
| **场景色调约束** | 剧本声明每个场景的色温/光线，消除同场景不同镜的色温突变 |
| **视频崩坏检测** | 抽首/中/尾三帧比对相似度，人物融化或漂移过大自动标记 |
| **回滚六重校验** | 版本存在性 / 文件完整性 / 任务运行态 / 内容一致性 / 差异统计 / 磁盘空间 |
| **18 类危险操作确认** | 一次性令牌 + 参数哈希绑定，篡改即拒 |
| **成本微元整数记账** | 1 元 = 1e6 微元，规避浮点累加误差 |

## 一致性：一个具体的例子

**同一段「山巅剑客」剧本，改造前后的对比：**

| | 改造前（每镜独立生成） | 改造后（定妆照 + 场景色调） |
|---|---|---|
| **服装** | 三镜三套衣服（浅蓝/深红/深蓝） | 三镜统一深红披风 + 白内衬 |
| **色温** | 02 突然从冷蓝变暖金 | 全段冷蓝 + 天边暖金 |
| **成本** | ¥16.8 | ¥12.6（多了定妆照 ¥0.2，少了重跑） |

**原因是 prompt 里只写了角色名没写外形，模型每次自由发挥。**
**解法是两层保障：剧本 `character_profiles` 存外形描述 + 首跑生成定妆照做参考图。**

## 实测数据

**全部来自真实调用，不是估算。**

| 项 | 实测 |
|---|---|
| **出图** | Seedream 5.5，15.2 秒/张，¥0.20/张 |
| **出视频** | Seedance 2.5-flash，80.5 秒/段（4 秒），87,300 tokens ≈ ¥4.02 |
| **配音** | 豆包语音 2.0，1.2 秒/句，4.5 元/万字符 |
| **一集成本** | 40 镜约 ¥168（视频占 95%） |
| **素材包导出** | 40 镜 221 MB，7.6 秒 |
| **并发写入** | 4 进程 × 25 次，丢失率 78% → 0% |

**成本结构里视频占 95%，所以「不是每镜都做视频」是省钱关键——
实测 40 镜里只有 21 镜值得做视频，成本从 ¥169 降到 ¥92。**

## 撞到的模型限制（写进设计了）

**这些不是查文档得到的，是实测撞出来的。**

| # | 限制 | 应对 |
|---|---|---|
| 1 | **seed 不可复现** —— 同 seed 出两次图 md5 不同 | 锁角色只能靠参考图 |
| 2 | **写实度到照片级会被拒** —— 图生视频报 `may contain real person` | 写实风格要加胶片颗粒降级 |
| 3 | **`reference_image` 字段被静默忽略** —— 必须用 `image` | 看 `usage.input_images` 确认 |
| 4 | **双人互动手部崩坏率 43%** —— 7 个镜头 3 个错 | 改局部特写后归零 |
| 5 | **emotion_scale 只有 1.0 生效** —— 0.5 返回空音频 | 硬编码 |
| 6 | **SSML 只支持 `<break>`** —— `<prosody>` 被念出来 | 改用 speech_rate 参数 |
| 7 | **API 不报错 ≠ 参数生效** | 必须查 usage 字段 |

**完整 10 条见 [实测边界.md](实测边界.md)。**

## 已知局限

诚实说明，避免误导：

- **单机设计**：自用系统不上分布式。要支持多人并发需迁状态到数据库、任务分发改队列、API 调用异步化（架构已留接口）
- **未训练 LoRA**：角色一致性靠参考图而非微调，只能做到「大概像」不是「完全一致」
- **仅支持 2D 风格**：3D 场景需要 Blender 建模，性价比低于 AI 出图
- **前端无框架**：238 KB 单文件，改起来慢，但不依赖 npm 生态
